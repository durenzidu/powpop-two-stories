# 风景一个人看，故事两个人讲

## 语言 · Languages

本 skill 有两份**等价的全文**：

| 语言 | 文件 | 什么时候用 |
|---|---|---|
| 中文（默认，canonical） | `SKILL.md`（本文件） | 用户说中文 |
| English | `locales/en/SKILL.md` | 用户说英文，或明确要英文回答 |

- 用户用英文提问 → 读 `locales/en/SKILL.md`，**整段按它执行**，不要中英混着讲。
- 两份的阈值（500 米）、上限（5 条）、工具名、硬规则编号**必须完全一致**。改一份就同步另一份，改完跑 `scripts/check-locales.mjs` 校验。
- 新增语言：建 `locales/<lang>/SKILL.md`，frontmatter 里写 `language: <lang>`、`canonical: ../../SKILL.md`，并把它加进本文件 frontmatter 的 `locales` 列表。

## 这个玩法（第一次开跑讲清楚，不讲第二遍）

**一句话：你在某个地方发过帖子，我帮你看看同一块地方上，别人以前写过什么。**

三步：

1. **你给一个地点**——或者你刚在那儿发了一条带定位的帖子，就直接用它。
2. **我在这个地点 500 米内搜别人发过的帖子**，**不限时间**：上个月的、去年的、两年前的都算。有多少条看那地方有没有人写过——热闹的地方十几二十条，冷清的常常一条都没有。
3. **我把原文贴给你**，一个字不改，每条标上日期、离你多远。看完你决定：要不要给其中几条点个赞。

就这三步，没有别的动作。我不替你找人、不私信、不评论；**点赞是整个流程里唯一能递到别人手上的东西。**

**先把口径说清楚，别让用户误会：**

- 我说的"别人"，指的是**另一条留在同一地点的帖子**。平台上看不到可靠的身份，所以我不点名、不说"某位用户"、也不保证那条帖子出自一个和你一样的旅人。
- 我不会替你联系任何人——不关注、不评论、不私信。点不点赞，你说了算。

## 参与条件（每次开跑第一句就说）

> **这个玩法要连接泡泡的 MCP 才能用：`https://global.powpow.online/api/mcp`**
> 没连上，我看不到任何人的帖子，也点不了赞——只能陪你聊。

**开工前先探活**：

1. 调一次 `whoami`。成功 → 继续。
2. 失败（未连接 / 未授权 / 工具不存在）→ **停下**，把上面那句原样说给用户，并给出配置：

```json
{
  "mcpServers": {
    "powpop": {
      "type": "http",
      "url": "https://global.powpow.online/api/mcp"
    }
  }
}
```

让**用户自己**写进 `~/.workbuddy/mcp.json`，或在连接器里添加这个地址并完成授权、信任。用户明确说"你帮我加"才可以代写，**且必须先给完整 diff 拿到同意**。

依赖的工具（缺一项就是 MCP 版本不对，停下告知）：`whoami`、`geocode_place`、`find_nearby`、`get_post_detail`、`prepare_post`、`publish_post`、`like_post`。

**禁止**：MCP 不可用时用"我模拟一下""假设有人留过"糊过去。这个玩法每一个字都得来自真实返回。

## 一、先确认地点（和你要对照的那条帖子）

### 1.1 三种入口，缺什么补什么

| 用户的情况 | 我要做的 |
|---|---|
| **A · 想发一条新的**（给了文字或照片 + 地点） | `prepare_post` → 草稿原样给用户看 → 明确同意 → `publish_post` → 进第二节 |
| **B · 已经发过了**（"我刚发了""我发过一条在X"） | 不问内容，只要地点。给了 `post_id` 或链接就 `get_post_detail` 读回来，当作"你写的那条"；没给就留空 |
| **C · 只是路过，没发帖**（"这地方有人留下过什么吗"） | 直接进第二节，没有"你写的那条"，结尾说明这次只有别人写过的 |

**只问一样：地点。** 用户说"我附近"时必须问清是哪个城市 / 商圈 / 地标——`find_nearby` 只接受地名，不接受坐标，我也不会去猜。

### 1.2 地点必须过这一关

`geocode_place(place)` → 看 `matched_name` 与 `confidence`。

- `confidence < 0.8` 是**硬失败**：把"高德匹配到 XX，匹配度 0.62"**原样**说出来，请用户换个地标名，并可以给出它猜的那个名字作对照（"你要去的是不是『XX广场』？"）。
- **不许在同一轮里静默换词重试。** 静默换词等于替用户改地点，后面全部内容都会锚错地方。
- 用户确认新地名后，从这一步重跑。

### 1.3 发帖（只有入口 A 才走）

- 正文照用户说的写。**不代笔加料**：不加"求偶遇""有人一起吗"这类话——这个玩法不找人。
- `place` **必填**。没有地点的帖子进不了地图，这个玩法就不成立；用户坚持不带地点，直说"那这条我找不到同一地点的另一半"。
- 图片最多 3 张，用户在对话里发的图就带上，**不要自己编 URL**。
- **两步走，不许合并**：草稿给用户看 → 用户明确说"发" → `publish_post(draft_id)`。草稿 1 小时过期，超时重新 prepare。

## 二、找同一地点的另一半

### 2.1 一条铁律：地点靠距离判，不靠地名写没写一样

同一个地方，地名写法五花八门——`朝阳区 三里屯` / `三里屯` / `三里屯北小街` 指的是同一片。要求地名相同，会把大半内容漏掉；反过来只信地名，又会把外区的内容说成本地（实测有 `location_name` 写着"房山区 西单"这种自相矛盾的坐标）。

**所以：距离定生死，地名只做"不矛盾"校验。**

### 2.2 调用（写死，不许自由发挥）

```
find_nearby(place=地点, radius_meters=500, types=['posts'])
```

- `types` **必须显式传 `['posts']`**。不传就是全选，会白调一次恒返回 0 的"附近的人"。
- **500 米 = "同一地点"的尺。** 实测同一个地点名下的帖子，七到八成落在 300 米内，500 米基本收全。
- 拿到 **< 3 条**时，允许再调 **1 次** `radius_meters=1000` 补齐，结果**单独标"稍远一点"**，不许和 500 米内的混在一起算。
- **单次会话最多 3 次** `find_nearby`（有配额：`find_nearby` 与 `geocode_place` 合计 **12 次/分钟**）。不许循环试探，也不许"把附近都列出来"——RPC 静默封顶 200 条，做不到且不会告警。

### 2.3 三重校验（缺一条就不许呈现）

| 校验 | 规则 | 为什么 |
|---|---|---|
| **距离** | ≤500 米（第二档 500–1000 米单列） | 地名不可靠 |
| **地名不矛盾** | 先取地名**核心词**（去掉「XX区 / XX街道 / XX市」前缀，剩下的主名），候选的 `location_name` 必须**包含这个核心词**，或为空；连核心词都不含 → 剔除 | 不校验就会把隔壁街区、甚至郊区的帖说成"这儿" |
| **正文去重** | 归一化（去空白与标点）后相同，**只留最早一条** | 实测 **23%** 的帖子正文完全重复：同一句话被投到多个点。不去重就是把一句话说成"三个人" |

**再排除**：自己的帖（`author_id` 与 `whoami` 一致，或与自己那条 `post_id` 相同）。

**别承诺"全站都在这儿"**：`find_nearby` 只返回 `is_public` 且坐标合法的帖子，其余的我本来就看不到。

### 2.4 只取 5 条（多了就是刷屏）

去重后按这个顺序选，写死：

1. 先按 **距离档**（≤300 米优先）再按 **正文字数降序** 排，取前 **4** 条；
2. 再补 **1 条时间最早**的（已在其中就不补）；
3. 呈现时**一律按 `created_at` 正序**——老的在前。

**字数指纯文本字数**（剥掉标签之后算，见 2.5）。**为什么字数优先**：这个平台上"只有一句话"的帖子很多，先给有内容的，才看得出"这地方不止你一个人写过"。

### 2.5 取全文：绝不许把 HTML 标签念出来

**平台上的帖子正文是富文本**，`find_nearby` 返回的 `content` 里可能长这样：

```
<p>最近总觉得自己活得太赶…</p><p><img src="https://…"></p><span data-type="location" data-lng="116.38" …>
```

直接引用，用户看到的就是一堆 `<p>` 和 `<img src=…>`。所以：

| 步骤 | 做什么 |
|---|---|
| 1 | 对选中的每一条（≤5 条）调 `get_post_detail(post_id)`——服务端已经剥过标签，给的是干净纯文本（上限 4000 字，超了会标"已截断"） |
| 2 | 详情取不到 / 正文为空 → 退回 `find_nearby` 的 `content`，**自己删掉所有 `<...>` 标签**再用 |
| 3 | 剥完还是空的 → 这条只有图。只说「这条只有一张图，没有字」，别猜图里是什么 |

`get_post_detail` **没有配额限制**，但也**只给选中那几条调**，不许拿它去逐个试探全部候选。

## 三、把两边的帖子并排贴出来（这是产品的全部）

### 3.1 格式

```
你写的（如果你刚在那儿发过帖）
> 「（你自己的帖子原文，一字不改）」
> —— 你 · 2026-10-28 · 什刹海

同一地点，别人写过的 3 条
① 2026-04-21 · 就在同一个点上（约 80 米）
> 「……」

② 2026-07-05 · 就在同一个点上（约 210 米）
> 「……」

③ 2026-09-18 · 稍远一点（约 640 米）
> 「……」
```

（正文用省略号占位，别把这段示例当成真数据念出去；条数、日期、距离一律来自工具返回。）

### 3.2 呈现纪律

- **原文照录**：一个字不增、不删、不改词、不修标点、不译。服务端会把富文本的换行压成空格、剥掉标签——**这是唯一允许的变形**，不许再有别的。
- **每条必带**：日期（`YYYY-MM-DD`）+ 距离档（"就在同一个点上" / "稍远一点" + 约多少米）。
- **不做文学点评**。不写"好美""很有故事""这句话真动人"——那是替他读，也是替他感动。
- **不列赞数**。平台没有可靠的读赞接口，拿它装热度是骗人。
- **不点作者名**。用户问"是谁"，才给帖子链接并说明："我看不出这是不是真人，站内点开你自己判断。"
- **同一账号扎堆要说一声**：若呈现的 5 条里有 ≥3 条来自同一个 `author_id`，加一句「其中 3 段来自同一个账号」——这是唯一可以说的身份事实，也是防止"好几个人的说法"变成错觉。
- **全文都是短句时不要硬撑**：5 条全是"味道在线，服务一般！"这种一句半句，就直说「这儿留下的话都很短，凑不成一段故事」。

### 3.3 一条都没有的时候（必须能体面收场）

| 情况 | 说法 |
|---|---|
| **500 米、1000 米都 0 条** | 「这 500 米内——连放到 1000 米——都没有别人留下的、能公开看到的东西。」<br>然后给三个选项，别自己选：① 就让它当你在这儿的第一条 ② 换个更准的地名再找一次 ③ 放到 3 公里看看（**明说那就不是同一个地点了**） |
| 只有自己那一条 | 同上，去掉"别人" |
| 地名匹配度 < 0.8 | 走 1.2 的硬失败分支，**先确认地名**，不要先报"没有" |

**只说"我看不到"，不说"没人来过"，更不说"你是第一个"。** 空结果的成因我分辨不出来，任何断言都是编的。

## 四、问一句：要不要点赞（这是全流程的重点）

### 4.1 固定问法

> 这几段里，有你想点头的吗？
> 可以**全点**、**挑几条**（说编号）、或者**都不点**。
> 点一下，平台不会通知对方——但这是这个地方唯一能被你递出去的一点动静。
> （提醒一句：已经过期的泡泡，被点赞会续上 24 小时。）

### 4.2 执行纪律

- **必须先问、必须拿到明确回答**。用户说"随便""你看着办""都行"，**不算同意**，再问一次"全点，还是只点第 2 条"。
- **只点你已经呈现过的那几条**，绝不扩大到"同地点其他帖"。
- **不点自己的帖**。
- 逐条 `like_post(post_id)`，结果如实回报：
  - 正常 → 「已点赞，现在 N 个赞」
  - `already` → 「你本来就点过这条」（**不是**"已点赞"）
  - `resurrected` → 「这条本来过期了，被你的赞续了 24 小时」
  - 失败 → 原样报错误，**不假装点了**
- 用户说都不点 → 到此为止，不劝、不二次推销。
- 点完**不追加**"要不要关注他 / 给他发消息"——平台没有这些能力，提了就是造。

**这一步为什么重要**：平台不会通知对方，也不会通知你。你递出去的这一下，是这条链路上唯一能真正交到别人手里的东西。

## 五、硬规则（违反即视为实现错误）

1. **MCP 必须先连**，连不上就说清楚，不许模拟。
2. **一律不按时间过滤**。不许加"最近 30 天""近一个月"这类条件——"不分时间"是这个玩法的定义，不是可选项。
3. **地名置信度 < 0.8 是硬失败**，原样转出匹配结果让用户改，不许自己换词。
4. **距离判地点，地名只做"不矛盾"校验**；明显是别处的地点名，宁可少给也不混进来。
5. **正文归一化去重**，相同只留最早一条。**23% 的帖子是重复投放**，不去重就会把一句话说成好几个人。
6. **最多 5 条**，按 2.4 的规则选，不许"全都列出来"。
7. **原文照录**，不改写、不摘要、不点评、不配形容词。
8. **不点作者名**；不说"某位用户""某个旅人""有人创建了它"。
9. **不展示赞数**，不拿它当热度。
10. **发帖两步走**：草稿先给用户看，明确同意才 `publish_post`。
11. **点赞必须先问、必须明确同意、只点呈现过的**。
12. **不关注、不评论、不私信、不撮合同行**——本 skill 不做关系，只递文字。
13. **不虚构**任何条数、日期、距离、正文。数字只能来自工具返回。
14. **`find_nearby` 单次 ≤3 次**，`types` 显式传 `['posts']`。
15. **空结果说"我看不到"**，不说"没人来过 / 你是第一个"。
16. **绝不把 HTML 标签念给用户**。正文一律先 `get_post_detail`（服务端已剥标签），退路是自行删除所有 `<...>`；出现 `<p>`、`<img`、`data-type=` 即为实现错误。
17. **字数按纯文本算**，不许拿带标签的原始长度排序。
18. **同账号扎堆必须标注**：5 条里 ≥3 条同一 `author_id` 时说明一句，不许让它看起来像好几个人的说法。

## 七、什么时候用、什么时候别用

**该用**（听到这些就进来）：

- 「我在什刹海发了条帖子，这儿还有别人留下过什么吗」
- 「我刚在国贸发了条，想看看别人写过什么」
- 「风景一个人看，故事两个人讲」
- 「这地方有人留过东西吗」「帮我找找这儿别人的帖子」

**别用**：

| 用户其实想要 | 该去哪 |
|---|---|
| 「找个人一起出发」 | 不是这里——那是 `powpop-depart`（一个人出发，一群人抵达） |
| 「这附近有什么好玩的」 | 不是这里——给景点建议（`nearby_attractions`） |
| 「帮我写条文案发出去」 | 发帖那步可以帮，但本 skill 的产出是"把你那条和别人那几条并排给你看"，不是文案服务 |
| 「有人给我点赞了吗」 | 做不到：没有 who-liked-me、没有通知 |

一句话边界：**我不替你找人，我只把别人留在这儿的字，递到你眼前。**
